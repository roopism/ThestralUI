# Qualification result reuse

Version 1 binds a decision to the committed merge tree, the trusted integration runner, the actual build inputs and the machine that executed the check. Any missing proof runs the existing check fresh. The hook never reads or writes reusable passes. Release and manual full runs execute every applicable check fresh.

## Groups and inputs

The JSON object in `tests/acceptance/suite-inputs.json` has `contractVersion: 1` and a `groups` map keyed by the 18 receipt names. Each entry has `reusable` (boolean), `mode` (tree, app or never), and arrays `exclude`, `extraInputs` and `envFacts`. Unknown groups, schemas, fields affecting identity, inputs and facts require fresh work. The default is the whole committed tree. Version one permits only the anchored glob patterns `docs/**` and `*.md` for groups that prove independence and enforce the exclusion on every relevant process.

| Groups | Mode |
| --- | --- |
| No weakening, Fast, Mac browser performance | never |
| Typed and unit rosters, Browser and visual rosters, Catalog build | tree |
| Packed component specifications, Packed consumers min, Packed consumers max, Packed bundle limits | tree |
| Portable web scenarios, Mac browser behavior, Mac visual comparisons, Scoped styles, Native package consumer, Linux browser behavior | tree |
| iPhone Simulator, Android standard and low-end | app |

Android app reuse covers functional checks only. Always evaluate the existing independent timing decision. Release and full fresh runs also measure timing. Rebuild the candidate app before device reuse. Preserve proven web-only selection for the iPhone. Bind scenario and driver identity to the actual selected scope and profiles. A passing smaller scope cannot satisfy a larger one.

Canonical JSON sorts object keys recursively by UTF-8 bytes. Arrays with set semantics are sorted by the same ordering, and structured arrays retain their specified order. Use SHA-256 on UTF-8 canonical JSON. Reject duplicate or ambiguous paths. For tree fingerprints the object is `{contractVersion,groupId,treeEntries,envFacts,extraInputs}`. Tree entries are sorted pairs of Git paths and blob IDs from recursive, NUL-delimited Git output. Include mode information as an additional identity fact so changing execute permission or file kind invalidates reuse. Unsupported input types require fresh work. The paths `scripts/gates/**`, `scripts/qualify.mjs`, `scripts/land.mjs`, `packages/policy/quality/**` and `tests/acceptance/suite-inputs.json` always participate. A pipeline change must run every group fresh on its adoption tree. Bind the identity of the trusted base judge as well as candidate pipeline content. Named external inputs need measured digests.

For app groups the object is `{contractVersion,groupId,appManifests,scenarioFiles,driverFiles,deviceImage,envFacts}`. Driver files include the protected pipeline inputs. Hash sorted app entries and contents. On iOS the root signature directory and embedded provisioning profile are excluded. Android uses the existing APK entry manifest and signed-file hash. Save both file and content identities, preserve types and links and fail closed on unknown entries. Use current system facts on qualification and landing. The fact IDs are node, lockfile, playwright-browsers, xcode, ios-runtime, android-system-image, vm-image, macos-build, hardware-model, gpu, display-scale, fonts and maestro. “unavailable” for any required fact means fresh. For Mac visuals require hardware-model, gpu, display-scale, fonts and macos-build.

## Enforcement and evidence

Worker A exports `environmentFacts(ids, context)`, `macCommand({root,exclude,command,args})`, `linuxCommand({root,exclude,command,args})` and `appIdentity(platform,path)`. Command wrappers return `{command,args}`. Identity returns `{fileSha256,manifestSha256}`. Facts return an object keyed by the requested IDs. Context includes root and may inject commands for tests. Place the actual Mac build, runner and static server inside the profile. Launch child browser servers outside and connect only over loopback. Keep resource reservations on the supervisor side. Linux uses unprivileged Landlock. Empty exclusions allow direct invocation. If enforcement is unavailable, use the existing full check with a whole-tree dependency and publish no narrowed record. A denied input read during a check fails it. Groups which read documentation retain it as an input. Fresh downstream groups must receive their real prerequisites, including packages, catalog builds, packed artifacts and reports. Restore only verified outputs or execute the producer.

Worker B owns fingerprints, policy, record validation, qualification and landing. Worker C exports `selectAudit(eligibleIds,seed)` (one group ID or null), `disableGroup(directory,groupId,reason)`, and `disabledGroups(directory)` (array of IDs). Directory is the shared receipt directory. If the local override cannot be verified, run fresh. Generate a new random seed per qualification, save it, and choose uniformly among eligible groups. If eligibility is resolved late, complete an audit before declaring a pass. Any disagreement fails qualification and disables the group. Keep the failed receipt and all evidence. The manual daily full run applies the same comparison.

Write `.git/uld-receipts/reuse/<fingerprint>.json` atomically with fingerprint, groupId, result (passed), sourceAttempt, sourceReceiptSha256, tree, retries (zero), createdAt, evidencePath and evidenceSha256. Only verified clean, committed qualification runs can publish, after all groups and the audit have passed. Reject retried, reused, failed, incomplete, diagnostic, dirty and unauthenticated sources. Verify source receipt, suite, history, mode and evidence before consumption. Preserve separate attempt files indefinitely. Use immutable evidence inside the canonical receipts directory. Validate paths, types and hashes, including during landing. On any error during selection run fresh. A landing mismatch refuses the merge.

Each group records result (passed, reused, failed, blocked or web-only), fingerprint, reusedFrom (source attempt), reuseReason, auditRerun and durationMs. Unavailable fields use null. Reuse records the original evidence, retains required VM and device details, and counts only elapsed time actually saved. Existing failed-attempt, history and landing protections remain enforced. A reused row qualifies as a pass only after verification. The qualification mode, release mode and daily full mode are distinct decisions. The TTL is 72 hours from the original pass. Inspect the last five fresh attempts for the group, including failures. Reuse does not reset the TTL or advance that window. A group with an unknown history runs fresh. Disable all reuse on release. An unknown or missing setting never enables a new shortcut.

## Adoption

The base runs the qualification and landing code; the candidate cannot certify its own merge. The existing frozen judge remains pinned. Its trusted supplemental reuse checks must run from the integration base at subsequent qualifications and landings. Keep the configured gate-code boundaries. Introduce the declarative matrix in a separately qualified data-only PR if needed. Compare the complete module suite, both canary controls and the source receipt before recording an adoption as successful. The daily full check is started manually.
