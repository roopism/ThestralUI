# Component inventory and contract review

The reference set covers 99 families, including underlying layout, interaction and workflow capabilities, plus explicit platform equivalents and gaps. The executable registry identifies the accountable maintainer, maturity, local story, behavior test, platform status and state owner. [Versioned family registry](component-inventory.mjs)

Run `npm run build:packages` and `node scripts/inventory.mjs` to verify the registry and print the counts. Supply an output filename to generate the binding report from the built declarations. It lists the declaration entry point, ref acceptance, recognized state properties, event names and common composition slots. The declaration carries the complete prop contract. Development candidates with story and test evidence qualify for the supported web-family count. Experimental exports without this evidence do not qualify. Headless regions, slots, hooks and aliases appear under their owning family. [Audit and regression fixtures](../tests/inventory.test.mjs)

The gate parses the built TypeScript declarations and verifies a one-to-one mapping between public value bindings and their family rows. A supported web row must have a runnable Storybook source using a binding in the family, directly or through its local example composition. Its test must reference a family binding or a family-specific observable in an executable journey. Unit cases exercise delegated events, controlled state, ref attachment and detachment, and slot rendering. Browser cases exercise keyboard and pointer behavior across local engines. [Public API contract tests](../tests/family-contracts.test.tsx) · [Browser journeys](../tests/browser)

The native Button, IconButton, FormField and Dialog have renderer coverage. Three journeys exercise the packed Release gallery on an iPhone Simulator, including the named IconButton that opens workspace help. Their experimental status reflects pending physical iPhone, Android and assistive-technology qualification. The renderer suite can run separately on any supported development host.
